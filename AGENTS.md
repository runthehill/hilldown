# Repository Guidelines

## Project Structure & Module Organization

HillDown is a Tauri v2 Markdown editor built with Vite, React, and TypeScript.

- `src/` contains the frontend app, file service, editor command helpers, styles, sample content, and tests.
- `src-tauri/` contains the Rust Tauri shell, capability permissions, config, Cargo manifest, and app icon assets.
- `docs/plans/` stores implementation plans for larger changes.
- `dist/` is generated by the frontend build and should not be edited by hand.

Keep reusable editing behavior in small TypeScript helpers, such as `src/editorCommands.ts`, so it can be tested without rendering the app.

## Build, Test, and Development Commands

- `npm install`: install JavaScript dependencies.
- `npm run dev`: start the Vite web app on `http://127.0.0.1:1420`.
- `npm run tauri dev`: run the desktop app with the Tauri shell.
- `npm run tauri build`: build the desktop app with the configured Tauri bundle targets.
- `npm test`: run Vitest unit tests.
- `npm run build`: type-check and build the frontend into `dist/`.
- `cargo check` from `src-tauri/`: verify the Rust/Tauri crate.

Use npm as the package manager and commit `package-lock.json` with dependency changes.

## Coding Style & Naming Conventions

Use strict TypeScript and 2-space indentation for frontend files. React components use `PascalCase`; functions, variables, and hooks use `camelCase`; CSS class names use `kebab-case`. Prefer explicit types for shared helpers and command data structures.

UI changes should stay dense and app-like: icon buttons for common formatting actions, segmented controls for view modes, and no marketing-style landing page.

## Testing Guidelines

Use Vitest for unit tests. Test pure editing behavior in `*.test.ts` files near the source they cover, as in `src/editorCommands.test.ts`. Add tests for selection handling, slash command filtering, Markdown snippet insertion, file-path helpers, and edge cases before changing editor command semantics.

Run `npm test` and `npm run build` before opening a pull request. Run `cargo check` when touching `src-tauri/`.

## Commit & Pull Request Guidelines

Use Conventional Commits, for example `feat: add table slash command` or `fix: preserve selection after bold`. Pull requests should include a concise summary, test evidence, linked issue when applicable, and screenshots or screen recordings for visible UI changes.

Before pushing any changes, treat the push as a release boundary: update the HillDown version number consistently in `package.json`, `package-lock.json`, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock`, and `src-tauri/tauri.conf.json`, then add or update the matching dated entry in `CHANGELOG.md`. Include the version and changelog updates in the commit that is being pushed.

## Security & Configuration Tips

Markdown preview HTML is sanitized with DOMPurify. Keep sanitization in place when changing rendering. Native file operations use Tauri dialog-selected paths plus `src-tauri/capabilities/default.json`; avoid broad filesystem scopes.
